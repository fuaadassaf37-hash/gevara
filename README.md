# سيرفر الديوان العسكري

سيرفر Node.js (Express + Socket.IO) يشغّل تطبيق `index.html` كما هو، ويوفّر
بالضبط الـ API التي يتوقّعها الكود الحالي في الصفحة:

- **تخزين مركزي**: كل تعديل يُرسَل عبر `POST /api/sync/operations` ويُكتب
  فوراً على القرص (لا يبقى شيء في الذاكرة فقط أو في localStorage وحده).
- **مزامنة فورية**: بعد قبول أي تعديل، يبثّ السيرفر الحدث `sync:operations`
  عبر Socket.IO لكل الأجهزة المتصلة حالياً — فتظهر التعديلات لديهم مباشرة
  دون الحاجة لتحديث الصفحة (هذا الجزء كان مبنياً بالفعل داخل `index.html`
  وينتظر فقط سيرفراً حقيقياً خلفه، وهو ما يوفّره هذا المشروع).
- **مصادقة بثلاثة أدوار** (Basic Auth): `admin` و`app` بصلاحية كاملة،
  و`viewer` بصلاحية قراءة فقط.
- **ضغط gzip**: يفعّل تلقائياً لتقليل زمن تحميل `index.html` (~8 ميجابايت).
- **نسخ احتياطية دورية**: كل 6 ساعات (وعند الإقلاع)، تُحفظ نسخة من قاعدة
  البيانات في `data/backups/` مع الاحتفاظ بآخر 12 نسخة فقط تلقائياً.
- **إغلاق آمن**: عند إعادة نشر Railway، ينتظر السيرفر اكتمال أي كتابة على
  القرص قبل الخروج فعلياً، فلا يُفقد آخر تعديل وصل للتو.

## التشغيل محلياً

```bash
npm install
cp .env.example .env   # عدّل كلمات المرور بداخله
npm start
```

يفتح التطبيق على `http://localhost:3000` (سيطلب المتصفح اسم مستخدم وكلمة مرور).

## النشر على Railway

1. ادفع هذا المجلد إلى مستودع GitHub (أو استخدم Railway CLI مباشرة).
2. أنشئ مشروعاً جديداً على Railway واربطه بالمستودع.
3. من تبويب **Variables** أضف نفس متغيّرات `.env.example` (على الأقل
   `ADMIN_USER` / `ADMIN_PASS` / `APP_USER` / `APP_PASS` / `VIEWER_USER` /
   `VIEWER_PASS`). لا حاجة لضبط `PORT` — Railway يوفّره تلقائياً.

### التخزين الدائم (مهم جداً)

بدون هذه الخطوة، ستُفقَد كل البيانات عند كل عملية نشر جديدة (Redeploy)، لأن
نظام ملفات Railway الافتراضي غير دائم:

1. من إعدادات الخدمة على Railway، أضف **Volume** جديد.
2. اربطه بالمسار `/app/data`.
3. أضف متغيّر البيئة `DATA_DIR=/app/data`.

بهذا يُخزَّن ملف قاعدة البيانات (`sync-store.json`) على قرص دائم في جذر
التطبيق فعلياً، ولا يُفقَد بين عمليات النشر.

## بنية المشروع

```
diwan-server/
├── server.js              # السيرفر: API + Socket.IO + طبقة التخزين
├── package.json
├── public/
│   ├── index.html          # التطبيق نفسه (بدون أي تعديل مطلوب عليه)
│   ├── persons-photos.json
│   └── shamcash-photos.json
└── data/
    └── sync-store.json     # يُنشأ تلقائياً عند أول تشغيل (السجل + آخر نسخة من كل قسم)
```

## ملاحظات

- لم يتم تعديل `index.html` إطلاقاً — كان جاهزاً بالفعل للعمل مع هذا النوع
  من السيرفر (نظام Precise Sync + Socket.IO مبني في الكود مسبقاً).
- عند وجود تعارض (تعديل جهازين لنفس القسم في نفس اللحظة تقريباً)، يعتمد
  النظام مبدأ "آخر نسخة صحيحة تفوز" مع إعادة محاولة تلقائية من العميل —
  وهذا موجود أصلاً في منطق الواجهة.
- حساب `viewer` يستطيع فتح التطبيق ومشاهدة البيانات، لكن أي محاولة حفظ منه
  تُرفَض من السيرفر (403).
